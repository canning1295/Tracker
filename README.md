# Tracker

Tracker is a personal iPhone + Apple Watch workout app scaffolded for the v1 WorkOutDoors replacement plan.

## Current V1 State

Implemented:

- iOS and watchOS SwiftUI app targets generated by XcodeGen.
- Main iPhone app target embeds the Watch app for physical-device install.
- iPhone and Watch apps both display as `Tracker`; bundle IDs derive from one `TRACKER_IOS_BUNDLE_IDENTIFIER` build setting in `project.yml`.
- Phone-only simulator target for local iOS UI checks when no watchOS simulator runtime is installed.
- Hostless `TrackerCoreTests` unit-test target for shared workout calculations.
- Shared activity, settings, interval, edit, workout-adjustment, heart-rate-zone, pace, split, summary, pause-detection, VO2-estimate, Watch control presentation, TCX export, and Strava upload models.
- iPhone tabs:
  - Activities
  - Summary
  - Workouts
  - Settings
- iPhone Summary includes current-week totals, active days, duration-weighted average heart rate, activity totals, heart-rate-zone time, recent-week trend rows, and VO2 history estimates from recent outdoor run/walk performance plus available age, sex, height, weight, resting-HR, and max-HR inputs.
- iPhone activity detail with map, shared route-timestamp-based or proportional fallback splits, metrics, exact start/end trim edits, pause removal, heart-rate-zone breakdown, and Strava status.
- iPhone time-based interval workout builder with add/edit, empty state, repeat, work, recovery, warmup, cooldown, label, intensity controls, and shared draft normalization for saved workouts.
- Programmed interval workouts start empty on new installs, so the Watch workout list shows only workouts you create and name.
- iPhone Settings includes a device-readiness checklist for install target, Apple Health, Apple Watch connectivity, Action Button shortcut setup, workout-control hardware validation, outdoor route permission, and Strava setup.
- iPhone settings for activity order, units, pace mode, max heart rate with calculated zone BPM ranges, VO2 inputs, Apple Health metric import, and Strava auto-upload.
- iPhone-to-Watch workout start requests through WatchConnectivity.
- iPhone-to-Watch settings, activity order, interval workout, and start-request transfers queue until WatchConnectivity activation completes.
- Watch-to-iPhone workout completion notifications through WatchConnectivity after the Watch workout and outdoor route save finish, so the phone refreshes HealthKit and processes the Strava queue with the completed route available.
- App Shortcuts for opening Tracker directly and starting each v1 activity, intended for Apple Watch Ultra Action Button and Shortcuts assignment.
- Shortcut start requests are consumed on iPhone to send the selected activity to the Watch, and consumed on Watch when the app becomes active.
- Watch activity selection:
  - Outdoor: Run, Walk, Bike by default.
  - Indoor: Run, Walk, Elliptical, Bike, Weights by default.
- Watch Crown-highlighted menus with page dots and overscroll navigation from environment selection to activity selection to start.
- Watch workout start flow shows HealthKit authorization/start status, verifies required Health write permissions after authorization, and reports route-recording location warnings.
- Watch workout start, pause/resume, and end controls backed by a shared tested control-state model.
- Watch controls enter a disabled Saving state after End to prevent duplicate finish requests while HealthKit finalizes the workout.
- Watch active elapsed time freezes during pause and resumes without counting paused wall time.
- Watch active metrics page.
- Watch heart-rate color uses the same max-HR zone boundaries shown in iPhone Settings on both the metrics page and outdoor map overlay.
- Watch live pace respects the iPhone pace setting: rolling window, whole workout, or current split for outdoor routes.
- Watch metrics are activity-aware: distance and pace are shown for distance-based workouts, while weights shows time, heart rate, and calories without fake distance.
- Watch outdoor map page with recorded route polyline, current location arrow, heading rotation, Crown zoom, zone-colored heart-rate corner, and paused-location filtering.
- Watch interval workout list and active interval progress with current step, repeat count, countdown, progress bar, and transition haptics.
- HealthKit workout start/save path on Watch.
- Watch workouts write HealthKit indoor/outdoor metadata so the iPhone import can classify recorded activities more reliably.
- HealthKit iPhone query path for workouts, routes, workout-associated heart-rate samples with time-window fallback, time-weighted heart-rate stats, age, sex, height, weight, and resting heart rate.
- HealthKit imports explicitly map only supported v1 workout types and skip unsupported activities instead of defaulting them to walks.
- App Intents for common start-workout shortcuts.

- Strava uploads persist Strava's upload ID, poll upload processing, and only mark a workout uploaded after Strava returns the final activity ID.

## Build

The project source of truth is `project.yml`.

Regenerate the Xcode project:

```sh
xcodegen generate
```

Build phone-only iPhone simulator smoke-test target:

```sh
xcodebuild -project Tracker.xcodeproj -scheme TrackerPhoneOnly -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO build
```

Build Watch device target:

```sh
xcodebuild -project Tracker.xcodeproj -target TrackerWatch -sdk watchos CODE_SIGNING_ALLOWED=NO build
```

For real use on your iPhone and Apple Watch, use the `Tracker` scheme in Xcode after selecting your signing team. That scheme embeds the Watch app. This workspace also includes `TrackerPhoneOnly` only to keep simulator UI checks possible on machines without a watchOS simulator runtime.

## Signing

The project includes HealthKit entitlements, explicit Xcode HealthKit capability metadata for both app targets, and the local paid `Toby Canning` Apple Developer team ID in `project.yml`. Simulator builds in this workspace used `CODE_SIGNING_ALLOWED=NO`, so the running simulator app reports a missing HealthKit entitlement. That is expected for unsigned local simulator smoke tests.

Current bundle identifiers:

- iPhone app: `com.toby.WorkoutTracker2026`
- iPhone simulator-only app: `com.toby.WorkoutTracker2026.phoneonly`
- Watch app: `com.toby.WorkoutTracker2026.watchkitapp`

These derive from `TRACKER_IOS_BUNDLE_IDENTIFIER` in `project.yml`; the Watch companion app plist also uses that same setting. If Xcode says a bundle identifier is unavailable, it cannot create the explicit App ID required for HealthKit. Xcode may then fall back to a wildcard provisioning profile, and wildcard profiles cannot include the HealthKit entitlement. Change `TRACKER_IOS_BUNDLE_IDENTIFIER` to another unique family, run `xcodegen generate`, then let Xcode create fresh managed profiles with HealthKit enabled.

When opening in Xcode:

1. Select your Apple Developer team for both targets.
2. Keep HealthKit enabled.
3. If Xcode still reports the bundle ID is unavailable, change `TRACKER_IOS_BUNDLE_IDENTIFIER` in `project.yml` to another unique family and run `xcodegen generate`.
4. Run the `Tracker` scheme on your iPhone and Apple Watch.
5. Approve Health and Location permissions.
6. Assign the `Open Tracker` shortcut to the Apple Watch Ultra Action Button and test launch behavior.

If the Watch target is listed as ineligible with `watchOS 26.2 is not installed`, install the watchOS platform component first:

```sh
xcodebuild -downloadPlatform watchOS
```

The signed generic device build has been verified from the command line with products outside the project folder:

```sh
xcodebuild -project Tracker.xcodeproj -scheme Tracker -destination 'generic/platform=iOS' \
  SYMROOT="$HOME/Library/Developer/Xcode/DerivedData/TrackerSignedCLI/Build/Products" \
  OBJROOT="$HOME/Library/Developer/Xcode/DerivedData/TrackerSignedCLI/Build/Intermediates.noindex" \
  -allowProvisioningUpdates build
```

Writing signed products to DerivedData avoids project-local filesystem metadata under `Documents` that can make `codesign` reject a build product.

For a repeatable signed device check, run:

```sh
TRACKER_IPHONE_DEVICE="<iPhone CoreDevice identifier or name>" \
TRACKER_WATCH_DEVICE="<Apple Watch CoreDevice identifier or name>" \
Scripts/verify-device-install.sh
```

The script prepares the Watch signing profile against the connected Watch hardware UDID, builds signed iPhone and Watch products into DerivedData, checks HealthKit entitlements, installs and launches the iPhone app, and attempts direct Watch install and launch only when Watch Developer Mode is enabled.

It intentionally requires device identifiers through `TRACKER_IPHONE_DEVICE` and `TRACKER_WATCH_DEVICE` instead of hardcoding local hardware identifiers in the public repository. Find connected identifiers with:

```sh
xcrun devicectl list devices
```

## Strava

The Strava client is wired for OAuth, refresh-token storage, TCX export, queued upload, and upload-status polling. It still needs a real Strava API application before it can be verified end to end.

Open [Strava API Settings](https://www.strava.com/settings/api) in Safari or a desktop browser and sign in to Strava. Look for `My API Application`. If the page is blank or does not yet show an application, create a new app named `Tracker`.

Suggested fields for Strava's API application:

- `Application Name`: Tracker
- `Website`: https://localhost
- `Authorization Callback Domain`: localhost

The Authorization Callback Domain must be:

```text
localhost
```

Tracker uses this callback URI:

```text
tracker://localhost/strava
```

Then enter the Strava API Client ID and Client Secret from Strava's `My API Application` page in Tracker's Advanced API Setup and tap `Connect Strava`. These are developer API values, not your Strava username or password. If the Strava app is installed, Tracker opens Strava for authorization and returns through the callback. If Strava is not installed, Tracker falls back to the in-app web authorization session. After connecting once, the Settings action changes to `Change Strava Login` so you can re-authorize or switch accounts.

Tokens and credentials are stored in Keychain. The Settings tab shows the required callback URI and required `activity:write` scope. The exporter currently produces TCX data with GPS and heart-rate trackpoints where HealthKit data is available.

Strava processes uploaded files asynchronously. Tracker stores the upload ID returned by Strava, polls the upload status, and stores the final Strava activity ID only after processing completes. If polling times out, retrying the upload status will poll the existing upload instead of submitting a duplicate file. If a local edit is saved before a workout has uploaded, Tracker queues a fresh adjusted TCX. Once Strava has a completed activity, v1 leaves that upload alone instead of creating a duplicate edited copy automatically.
